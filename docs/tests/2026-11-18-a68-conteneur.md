## Construction et choix

- Contexte à la racine : `agent` importe les paquets workspace `contrats`,
  `jugement`, `memoire`, ainsi que deux modules existants de
  `automatisation/scene/`. Ils sont copiés, pas modifiés. `.dockerignore` est
  une liste d'autorisation : ni `.git`, ni clés, ni vault, ni `banc/` dans
  le contexte. Les fichiers `.env*` sont aussi explicitement exclus.
- Node 24 (TypeScript natif), Debian bookworm, Chromium et chromedriver
  fournis ensemble par apt. Version mesurée : Chromium 156.0.8078.79.
- Nouvelle dépendance système : Python/venv pour le pont officiel
  `hai-agents[cli,browser]==1.5.1` (même version que le pont de la VM).
  `tini` relaie les signaux et récolte les processus ; certificats et fontes
  servent au HTTPS et au rendu. Aucune dépendance JS ajoutée.
- **Headless `--headless=new`, sans Xvfb** : le pont se rattache au CDP du
  Chrome déjà lancé, il n'exige pas d'écran. Preuves : 13 relevés PNG
  1280 × 900, 13 réponses Holo `fait`, navigation réelle par H.
  DPR 1 contrôlé par le moteur existant, profil couleur sRGB.
- Processus sous l'utilisateur `node`, port CDP sur loopback, aucun port
  publié. `--disable-dev-shm-usage` évite la limite `/dev/shm` Docker.
  `--no-sandbox` est nécessaire à ce lancement conteneurisé sans configuration
  de sandbox hôte ; **cela réduit l'isolation de Chromium**. Ne pas traiter
  cette image seule comme une frontière de sécurité pour des sites hostiles.
- Les avertissements DBus/UPower (pas de bureau dans l'image), Vulkan et
  WebGL logiciel sont visibles dans le journal. Environnement vérifié dans
  le conteneur : utilisateur, PATH, Chromium et pont présents ; ils n'ont pas
  empêché les relevés. Pas d'ajout d'un démon de bureau pour les masquer.

## Reconstruire et relancer

Depuis un clone, avec Docker et une clé de développement déjà exportée dans
le shell (ne jamais l'écrire dans la commande, l'image ou un fichier) :

```sh
git clone --branch a-68-conteneur https://github.com/Hisseiny/Horama-.git /tmp/horama-a68-clean
/usr/bin/time -p docker build --no-cache -t horama:a68 /tmp/horama-a68-clean
docker images horama:a68
docker run --rm horama:a68 --help
mkdir -p "$HOME/a68-data"
# Le compte node de l'image a l'UID 1000 : donner à cet UID l'accès au volume.
docker run -d --name horama-a68 --memory=2g --cpus=2 \
  -e HAI_API_KEY -v "$HOME/a68-data:/data" horama:a68 \
  --url https://www.eugeniaschool.com --sans-base
while [ "$(docker inspect -f '{{.State.Running}}' horama-a68)" = true ]; do
  docker stats --no-stream horama-a68
  docker exec horama-a68 cat /sys/fs/cgroup/memory.peak
done
docker logs horama-a68
docker inspect -f '{{json .State}}' horama-a68
```

Les chemins persistants sont `/data/exploration` (JSON et captures) et
`/data/vault` (notes et références). Pour reproduire un premier passage,
utiliser un volume vide. Une réutilisation compare les références existantes.
Le lanceur réserve ces chemins et CDP 9333 ; `--max` reste celui du moteur.
Il transmet SIGTERM/SIGINT au moteur en SIGINT pour son annulation et ferme
Chrome en `finally`. L'annulation pendant une vraie session n'a pas été
testée : prévoir un délai d'arrêt suffisant et vérifier le quota après arrêt.
