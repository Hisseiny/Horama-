# #67 — découverte des sites construits en JavaScript

## Règle du repli

Après le HTML initial et les sitemaps, si la file de candidats autorisés contient moins de `min(max, 3)` pages et qu'un `render` est disponible, lire le DOM rendu de la page initiale. L'accueil compte dans ce seuil. Les pages suivantes peuvent également être rendues. Sans `render`, le comportement reste identique.

Le DOM (`document.documentElement.outerHTML`, avec `location.href`) repasse dans `links()` : priorité nav/header/footer, plafonds par rubrique existants, exclusions des fichiers, connexions et actions de formulaire. Une page contenant un formulaire reste visitable. Aucun clic ni soumission n'est effectué.

Chaque rendu consomme une tentative dans le budget commun `max * 3`, comme les tentatives HTML de pages ; robots et sitemaps gardent leurs budgets existants. Le seuil compte des candidats, pas des pages dont le GET a déjà réussi. Le rendu initial alimente les règles de répartition par rubrique avant leur calcul.

`renderPage(port, url, allowed)` ouvre un onglet temporaire avec `PUT /json/new`, intercepte les requêtes Document avant leur envoi (y compris redirections et cadres), attend le chargement puis `waitForVisibleStable`, lit le DOM et ferme l'onglet dans `finally`. Le prédicat `allowed` réutilise les règles de découverte, notamment robots. Il est aussi transmis aux rendus injectés. Délais : création/fermeture 2 s chacune, opération CDP 15 s, garde externe de découverte 20 s (laisse le temps de fermer l'onglet après expiration CDP). Un échec rejoint `errors` et ne fait pas tomber la découverte.

Dans l'explorateur, `deps.render` est injectable ; le rendu Chrome est activé par défaut en fonctionnement réel. Lorsqu'un fetch est injecté sans render, Chrome est désactivé pour conserver les tests hors réseau rapides.

## Essai public réel, sans H

Chrome lancé avec :

```sh
google-chrome --headless --no-sandbox --disable-dev-shm-usage \
  --remote-debugging-port=9257 --user-data-dir=/home/ubuntu/a67-chrome \
  --force-device-scale-factor=1 --window-size=1280,900 about:blank
```

Mesure via `node --input-type=module`, import de `discoverPages` et `renderPage` depuis `./agent/src/exploration/pages.ts`, en série :

```js
for (const [url, max] of [['https://demo.realworld.show', 15], ['https://pokedex.org', 8]]) {
  for (const rendered of [false, true]) {
    const start = Date.now();
    const result = await discoverPages(url, { max, ...(rendered ? {
      render: (url, allowed) => renderPage(9257, url, allowed)
    } : {}) });
    console.log(JSON.stringify({ url, max, rendered,
      duration_s: (Date.now() - start) / 1000, ...result }));
  }
}
```

Robots et HTML vérifiés avant la mesure par GET Python `urllib.request` (timeout 15 s), puis relus par la découverte :

- `https://demo.realworld.show/robots.txt` : HTTP 200 mais shell HTML Angular, aucune directive robots, donc aucune interdiction déclarée. Le sitemap renvoie aussi le shell : erreur XML visible avant **et** après. HTML initial sans lien navigable exploité par le parseur.
- `https://pokedex.org/robots.txt` : HTTP 200, `User-agent: *` puis `Allow: /`. Sitemap 404. HTML initial avec seulement des liens externes, aucun autre candidat interne.

Aucune connexion, aucun formulaire soumis, aucun contournement anti-robot ; pas d'anti-robot rencontré. Une seule mesure avant/après par site, mêmes max et plafonds. Durée murale incluant robots, sitemap et rendus ; pas de prétention statistique.

## Limites et non testé

- Shadow DOM non sérialisé par outerHTML, liens sans href/onclick, routes uniquement dans le fragment : non découverts.
- La stabilité est bornée et peut manquer des liens injectés très tard ; ni scroll, ni clic sur menu, ni consentement cookies.
- Scripts et sous-ressources nécessaires au rendu s'exécutent normalement, mais toutes les ressources interceptées par CDP Fetch sont filtrées contre les hôtes locaux/privés, sauf l'hôte:port exact exploré. Les Documents restent aussi soumis à robots et aux exclusions. Ce n'est pas un bac à sable réseau intégral : pas de résolution DNS anti-rebinding, et les connexions WebSocket ne sont pas interceptées par le domaine CDP Fetch.
- Les rendus injectés doivent respecter le prédicat `allowed` ; l'injection ne permet pas à Horama d'intercepter elle-même leur trafic.
- Non testé : H, authentification, anti-robot, pages réelles avec expiration du délai, Chrome absent réellement (erreur simulée), comparaison visuelle de captures. Aucune interface utilisateur n'est modifiée.
- Aucune dépendance ajoutée ; aucun contrat modifié.
