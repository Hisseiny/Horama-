# #67 — fin propre sur blocage et relevé indisponible

## Portée des blocages après relecture

En découverte, seule l'adresse de départ (redirections comprises) peut arrêter
le passage pour une page introuvable, une connexion demandée ou un blocage.
Robots et plans de site n'arrêtent le passage pour ce détecteur que sur un signal
anti-robots ; leur absence HTTP 404/410 n'est pas un blocage.
Une sous-page indisponible est écartée par la découverte, sans empêcher les
autres requêtes ni créer de raison globale de blocage.

Dans Chrome, une page introuvable ou une connexion demandée sur une sous-page
ne marque que celle-ci `non_visitee`, avec sa raison. H reçoit les autres relevés,
jamais un nouvel essai vers cette page. Une protection anti-robots dans Chrome,
ou n'importe quel blocage sur la page de départ, conserve l'arrêt global.

Tests sans réseau externe : un sitemap contient `/missing` et `/healthy` ;
HTTP 404, 410, 401, 403, formulaire de connexion et challenge HTML sont simulés
en découverte et via CDP. La page normale reste visitée, sauf protection
anti-robots rendue qui conserve volontairement la portée globale.

la phrase est conservée dans `agents[].raison`, `pages[].raison` et les constats
